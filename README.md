# Gemini Node.js Quickstart and TCM-Tongue YOLO

This repository contains small Gemini/Node.js examples and a YOLOv11 training
and inference workflow for the 20 classes declared in
`TCM-Tongue/dataset/tcm_tongue.yaml`.

## What is and is not in Git

The dataset archives, extracted image datasets, model weights, training runs,
`.env`, Python virtual environments, and `node_modules` are intentionally
excluded. The dataset archive in the development workspace is several
gigabytes and is not suitable for a regular GitHub repository. Do not upload
the dataset or trained weights without confirming the dataset license and
having permission to redistribute them.

Obtain the dataset separately from its original source, following the
attribution and citation information in
[`TCM-Tongue/README.md`](TCM-Tongue/README.md). Place/extract the dataset so
this path exists:

```text
TCM-Tongue/dataset/shezhenv3-coco-percent-3/
  train/images/
  train/labels/
  val/images/
  val/labels/
  test/images/
  test/labels/
```

The relative dataset path is configured in
[`TCM-Tongue/dataset/tcm_tongue.yaml`](TCM-Tongue/dataset/tcm_tongue.yaml).
`train.py` resolves it relative to its own location, so it works from a
different checkout directory and does not depend on Ultralytics' global
dataset setting.

## Train on an NVIDIA GPU workstation

Install Git, Python 3.11 (recommended), and a compatible NVIDIA driver on the
workstation. Create a fresh virtual environment in the cloned repository.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Install the PyTorch build that matches the workstation's driver using the
command generated by the official PyTorch selector:
<https://pytorch.org/get-started/locally/>. Then install Ultralytics:

```powershell
python -m pip install -r requirements-training.txt
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CUDA is not available')"
```

Do not continue with GPU training until the first command prints `True` and
the GPU name.

### Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

Install the matching PyTorch build from
<https://pytorch.org/get-started/locally/>, then run:

```bash
python -m pip install -r requirements-training.txt
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CUDA is not available')"
```

### Start training

After placing the dataset in the expected location:

```bash
python TCM-Tongue/dataset/train.py
```

The script detects CUDA automatically. With CUDA available it uses the GPU
configuration (YOLO11s, up to 100 epochs, full dataset, 640-pixel images, and
batch size 16). Adjust `batch` in `train.py` if the GPU runs out of memory.
Without CUDA it deliberately uses a short CPU smoke-test configuration (one
epoch and 5% of the training data); that is not a full training run.

Training checkpoints and metrics are written under
`TCM-Tongue/dataset/TCM_Tongue_Runs/` and are intentionally not committed.

## Run inference

Run from the repository root. The script uses the newest local `best.pt` and,
if no image argument is provided, selects a test image:

```bash
python TCM-Tongue/dataset/infer_yolo.py
python TCM-Tongue/dataset/infer_yolo.py path/to/tongue-image.jpg
```

## Node.js examples

Install Node.js and the project dependencies:

```bash
npm ci
```

Copy `.env.example` to `.env` and set `GEMINI_API_KEY` only if you intend to
run the Gemini examples. Never commit `.env` or paste an API key into source
code. The YOLO training and inference scripts do not need a Gemini key.

## Run the doctor dashboard on Windows

The Vite/React app opens the doctor-facing Vital Signs dashboard first. It
reuses `vital-signs-system/doctor_dashboard.html`; its current sample data is
for preview only, and selected JSONL files are read locally in the browser.
The existing Express API can run separately on Ubuntu. In the repository root:

```powershell
npm ci
```

Create an ignored `.env.local` file and set the Ubuntu server's private LAN or
VPN address. Do not put `GEMINI_API_KEY` in a `VITE_` variable; keep that key
only in the Ubuntu backend's `.env`.

```dotenv
VITE_BACKEND_URL=http://<ubuntu-private-ip>:3000
```

Start the dashboard and open the printed local URL (normally
`http://127.0.0.1:5173`):

```powershell
npm run dev
```

### Share a public preview

The repository is configured to deploy the **static demo dashboard** to GitHub
Pages when changes are pushed to `master`. After the first successful workflow,
open:

<https://nghiant2921-creator.github.io/homed/>

To enable the first deployment, open the repository's **Settings → Pages** and
select **GitHub Actions** as the build and deployment source. The workflow is
`.github/workflows/deploy-pages.yml`. The local Vite URL remains unchanged.
This public page contains only the demo dashboard; do not load, publish, or
send real patient data there. GitHub Pages is static hosting and does not run
the Ubuntu backend or process Gemini API requests.

The top bar links to the official Gemini API documentation. This is a
documentation link only: the dashboard does not yet call Gemini or the Express
API. Vite proxies `/api/*` requests to `VITE_BACKEND_URL`; without `.env.local`
it uses `http://localhost:3000`. Existing backend routes include
`/api/analyze/tongue`, `/api/analyze/fall`, and `/api/analyze/holistic`.
Keep `GEMINI_API_KEY` on the Ubuntu backend; never expose it in a `VITE_`
variable. Keep the Ubuntu API on a trusted private network or VPN; do not
expose port 3000 directly to the public Internet.

To check a production bundle:

```powershell
npm run build
```
